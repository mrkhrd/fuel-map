# fuel-map

Карта наличия топлива на АЗС: данные [toplivo.tbank.ru](https://toplivo.tbank.ru)
объединяются с [sberazs.ru](https://sberazs.ru) и картой АЗС
[Альфа-Банка](https://alfabank.ru) (у Альфы — ещё и цены),
маршруты по реальным дорогам (OSRM).

## Возможности

- АЗС на карте (Leaflet + OSM), подгрузка по видимой области; цвет маркера —
  объединённый статус трёх источников (Сбер и Альфа учитываются только как
  свежий позитивный сигнал — устаревшие данные не перекрывают Т-Банк)
- Станции Сбера и Альфы сопоставляются с Т-Банком по координатам (до 150 м);
  у Альфы нет bbox-API — вся страна одним ответом (~3 МБ gzip), кэшируется
  на 5 минут и режется по видимой области на клиенте
- Бейдж у маркера — по строке на банк: время последней оплаты (зелёный < 3 ч,
  серый > 24 ч), у Сбера — число оплат; цветные чипы наличия по видам топлива
- Попап: секции Т-Банк, Сбер и Альфа — наличие по видам топлива, лимиты
  литров, оплаты, уверенность оценки; у Альфы — цены и бренд АЗС
- Фильтры: по виду топлива (OR двух источников: АИ-92…АИ-100, ДТ, пропан, метан),
  по статусу (есть / возможно / нет / нет данных) и по свежести — ползунок
  «не старше» (шаг 30 мин, до 12 ч, по умолчанию выключен)
- При выбранном топливе возраст должен стоять на самом топливе: оплата на
  станции — не свидетельство об АИ-95 и его не датирует. Отметку времени по
  видам топлива дают только `recentEvents` Т-Банка (есть не у всех АЗС) и
  `last_transaction_at` Альфы, и только когда вердикт отметки — тот самый, что
  показан: «нет АИ-95» 47 минут назад не датирует зелёное «есть», а зелёное со
  слов Альфы стар́о настолько, насколько стара она сама.
  Сбер по видам топлива времени не даёт вовсе — он может покрасить маркер, но
  не датировать его. Нет отметки (или статус «нет данных») — возраст
  неизвестен, и при включённом ползунке АЗС скрыта. Фильтр строгий: на 30 мин
  в поле зрения остаются единицы. С фильтром «Все» берётся просто самая свежая
  оплата из трёх источников
- В попапе у видов топлива Т-Банка показан 🕑 возраст сообщения именно об этом
  топливе, у Альфы — 💳 время её последней транзакции по нему: по ним и
  работает фильтр свежести
- Маршрут (TSP) по видимым или выбранным станциям (ctrl+клик — добавить сразу,
  либо попап: Старт / Точка / Финиш); матрица времени и геометрия — OSRM,
  решатель nearest-neighbour + 2-opt с фиксацией старта/финиша; fallback
  по прямой при недоступности роутера; ссылка «открыть в Я.Картах»

## Запуск

Rust-хост (~240 КБ, `index.html` вшит при сборке, TLS из ОС):

```
build-rust.bat                        # → target\release\fuel-host.exe
fuel-host.exe [порт] [host=ip ...]    # порт по умолчанию 8000
```

`host=ip` закрепляет адрес внешнего API (аналог docker `extra_hosts`) — запасной
вариант на случай, если DNS отдаёт нерабочий адрес. Сейчас всем трём источникам
пин не нужен (sberazs.ru какое-то время жил за DDoS-Guard, но снова отвечает
напрямую — старый пин `sberazs.ru=213.171.31.57` мёртв, не используйте его):

```
fuel-host.exe 8000 sberazs.ru=185.71.64.253
```

Альтернативы: `python server.py` или PyInstaller-сборка `build.bat`
(~9 МБ, `dist\fuel-map-server.exe`).

Сервер — статика + прокси `/api/*`, `/sber/*`, `/alfa/*`, `/osrm/*` (у внешних
API нет CORS-заголовков). Для alfabank.ru прокси проходит анти-бот проверку
(307 + cookie) и притворяется браузером; gzip от внешних API отдаётся клиенту
как есть. `index.html` рядом с exe имеет приоритет над встроенным.
Все запросы клиента и походы к внешним API логируются с таймингами.

## Сбор истории — `collector.py` (фаза 0)

Опрашивает три источника по расписанию и складывает сырые ответы в архив;
разбора данных пока нет — историю собирают один раз, и если парсер потом
окажется с ошибкой, архив можно переиграть, а потерянные дни — нет.

```
python collector.py [порт-прокси]      # по умолчанию 8000
python collector.py 8123 --once        # один цикл и выход
```

Ходит **через прокси `fuel-host`**, а не напрямую: TLS, обход анти-бота Альфы,
российский корневой CA, gzip и пины адресов уже работают там и должны жить в
одном месте. На старте делает проверку — если на порту отвечает что-то другое,
падает сразу, а не пишет неделю успешно записанных 404.

- Регион — Санкт-Петербург (`59.80–60.10 × 30.10–30.60`), константа `REGION`
- Т-Банк обходится квадродеревом: тайл, вернувший 300 (потолок ответа), делится
  на четыре и опрашивается заново. Город — 5 тайлов и **572 АЗС**; одним bbox
  их видно 300, то есть карта показывает чуть больше половины
- Расписание: Т-Банк и Сбер раз в 5 мин, Альфа раз в 15 мин (у неё один ответ
  на всю страну, ~20 МБ / 2,4 МБ gzip, а медианный возраст её отметок по
  топливу ~16 ч — чаще спрашивать нечего)
- `fuel.db` (SQLite): таблица `poll` — по строке на каждый HTTP-запрос с
  таймингами, кодом, числом станций, флагом потолка и ошибкой. Строки живут
  вечно даже после удаления тела: пропуски и сбои — это тоже данные
- Тела адресуются по содержимому (`raw/<источник>/<sha>.json.gz`), поэтому
  неизменившийся ответ не стоит ничего. На практике повторяются тайлы Т-Банка и
  ответы Альфы между опросами; Сбер — нет, его `dataVersion` меняется за
  секунды. Хранение 14 дней, затем тела удаляются, `poll` остаётся
- `fuel.db`, `raw/` и `collector.log` — в `.gitignore`

## Релизы и Docker

Каждый push в `main` автоматически повышает patch-версию (тег `vX.Y.Z`),
публикует GitHub Release с `fuel-map-vX.Y.Z-win64.zip` и docker-образ;
версия зашита в бинарник и печатается при старте:

```
docker run -d -p 8000:8000 ghcr.io/mrkhrd/fuel-map:latest
docker run -d -p 8123:8123 ghcr.io/mrkhrd/fuel-map:latest 8123   # свой порт
```

При необходимости адрес пинится через `--add-host host:ip` (в compose —
`extra_hosts: ["host:ip"]`), см. `host=ip` выше.

## Автозапуск на Windows

```powershell
netsh advfirewall firewall add rule name="fuel-map" dir=in action=allow protocol=TCP localport=8000
schtasks /Create /TN "fuel-map" /SC ONSTART /RU SYSTEM /TR "C:\path\to\fuel-host.exe"
schtasks /Run /TN "fuel-map"
```

## Замечания

- API Т-Банка отдаёт не более 300 АЗС на запрос и не умеет постраничность —
  при сильном отдалении карта показывает лишь часть, об этом пишет строка
  статистики в панели.
- Публичный OSRM demo-сервер rate-limited; при недоступности маршрут строится по прямой.
- Сервер без аутентификации и HTTPS — рассчитан на локальную сеть.
